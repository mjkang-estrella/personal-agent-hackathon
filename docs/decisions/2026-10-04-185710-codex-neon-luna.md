# Route model calls through Neon AI Gateway

- Date: 2026-10-04
- Status: accepted
- Owner: Codex / user-requested model migration

## Context

The user requested replacing direct OpenAI billing with their Neon AI Gateway credits, and selected the Luna model offered in Neon's catalog. The branch catalog reports `gpt-5-6-luna` enabled; a live Responses API request succeeded.

## Decision

Use `gpt-5-6-luna` at the existing JobSwitch branch's Neon gateway. Configure the OpenAI-compatible SDK with an explicit Neon token and Responses base URL. Keep Mastra, the application database, approval rules, and other integrations intact. Missing gateway credentials fail closed; there is no direct OpenAI fallback.

Require the existing independent `SESSION_SECRET` for workspace cookies and portal capability signatures. Provider credentials are no longer used for either signature. Prepared claims refresh the stored capability hash at submission; confirmed submissions keep their idempotency records.

## Rationale

The user wants AI usage charged to Neon credits. The compatible SDK preserves structured output, streaming, tool use, and the existing Mastra agent architecture.

## Consequences

Neon AI Gateway credits and model access are required. `OPENAI_API_KEY` is no longer needed by the app. Existing session cookies remain valid because the deployed app already had a dedicated `SESSION_SECRET`. The model changes from direct OpenAI gpt-6-luna to Neon's catalog model gpt-5-6-luna, as explicitly selected by the user.
